# CLAUDE.md — Project recap

Snapshot of how `quale-conviene` is structured today (code + infrastructure),
written so a fresh contributor (or a future agent session) can ramp up
without re-reading the whole repo.

---

## 1. What the app does

**Quale Conviene** is an Italian web utility that normalises supermarket
prices to a single comparable unit so users can answer the question
"which package actually costs less per litre / per kilo / per piece /
per wash?".

The user picks a category (e.g. `acqua`, `pasta`, `detersivo-lavatrice`)
and fills in 2–5 rows with `prezzo + formato + quantità`. The app
computes `€/base-unit` for each row, ranks them and renders:

- a results table with the winner highlighted
- a planner ("quanto costano N litri?" / "quanti litri con N €?")
- a share URL that encodes the comparison so any visitor sees the same
  rows

For products that don't fit any of the 20 built-in categories, the user
can build an ad-hoc comparison at `/confronta` (wizard → builds a
`CategoryDefinition` on the fly and hands it to the same comparator).

The site is privacy-first: no cookies, no login, no profiling. Only the
edge-level analytics that come automatically with the Cloudflare zone.

Public URL: <https://qualeconviene.app>

## 2. Tech stack

- **Runtime**: Cloudflare Workers (SSR + asset serving in one
  deployable). `compatibility_date: 2025-09-02`, `nodejs_compat` flag.
- **Framework**: TanStack Start (React 19 + TanStack Router with
  file-based routing, SSR via Workers).
- **Bundler**: Vite 8 with the `@cloudflare/vite-plugin` and the
  TanStack Start plugin.
- **Styling**: Tailwind CSS v4 (`@tailwindcss/vite`), plus a small set
  of custom utilities defined via `@utility` in `src/styles.css`.
- **UI primitives**: shadcn-flavoured components in
  `src/components/ui/*` (Radix under the hood via `radix-ui`), wrapped
  by branded versions in `src/components/app/*`.
- **Forms**: `@tanstack/react-form` (only used inside the bulk-paste
  flow; the rest of the forms are plain React state).
- **Schema/validation**: `zod` (light usage in `bulk-paste.ts`).
- **Icons**: `lucide-react`.
- **Tests**: Vitest + `@testing-library/react` + jsdom.
- **Lint/format**: Biome (`biome.json`, `indentStyle: tab`,
  `quoteStyle: double`).
- **Package manager**: Bun (`bun.lock` checked in; scripts run via
  `bun run …`).

## 4. Routes & rendering

All routes are SSR'd by the Worker. The HTML is then hydrated client
side. TanStack Router handles client-side navigation after hydration.

| Path                | File                       | Notes                                    |
| ------------------- | -------------------------- | ---------------------------------------- |
| `/`                 | `routes/index.tsx`         | Hero, recent comparisons, search, grid   |
| `/{categorySlug}`   | `routes/$category.tsx`     | One route per built-in category (20)     |
| `/confronta`        | `routes/confronta.tsx`     | Wizard or saved custom comparison (noindex) |
| `/contatti`         | `routes/contatti.tsx`      | Feedback/contact + gradient email card   |
| `/terms`            | `routes/terms.tsx`         | Generic ToS                              |
| `/privacy`          | `routes/privacy.tsx`       | GDPR informativa                         |
| `/cookie`           | `routes/cookie.tsx`        | Cookie policy (we don't set cookies)     |
| `/sitemap.xml`      | `routes/sitemap[.]xml.ts`  | Auto-generated from `CATEGORIES`         |
| `/robots.txt`       | `routes/robots[.]txt.ts`   | Allow-all + sitemap reference            |

Each page sets `<title>`, description, OG/Twitter tags, and a canonical
`<link>` via `seo.ts → buildHomeMeta / buildCategoryMeta /
buildCanonicalLinks`. Canonicals are emitted as `<link>` (not `<meta>`,
which Google ignores).

Category pages also embed three JSON-LD blocks (`Article`,
`BreadcrumbList`, optional `FAQPage`) — see `buildCategoryJsonLd()`.

## 5. Domain model (`src/lib/pricing.ts`)

```ts
type ContextId = "liquid" | "weight" | "unit" | "dosage";

interface CategoryDefinition {
  slug: string;
  name: string;
  description: string;            // meta description + intro
  intro?: string;
  longDescription?: string;       // SEO long-tail copy below the comparator
  guideTitle?: string;            // h2 above sections
  sections?: { heading: string; body: string }[];   // h3 subsections
  context: ContextId;
  baseLabel?: string;             // singular base unit name
  baseLabelPlural?: string;
  levels: UnitLevel[];            // hierarchy of packaging levels
  keywords?: string[];            // synonyms for the home search
  related?: string[];             // slugs of related categories
  faq?: { q: string; a: string }[];
  sampleEntries?: ProductEntry[];
}
```

A **context** is the math axis:

- `liquid` — input volumes in L/cl/ml, output `€/L`
- `weight` — input mass in g/kg, output `€/kg`
- `unit`   — count-based, output `€/piece` (custom base label)
- `dosage` — volume per pack + declared doses; output `€/dose`
  (detergents declaring "44 washes per bottle")

A **CategoryDefinition** layers labels and packaging hierarchy on top of
a context. `compute(category, entries)` returns the ranked
`ComputedEntry[]` consumed by `ResultsTable` and `PurchasePlanner`.

Built-in catalog: 20 records in `src/data/categories.ts`. Each one has
a long-form SEO body (longDescription + 4 sections + 7-8 FAQ entries)
and 3-4 `sampleEntries` shown on first visit.

### Custom comparisons (`src/lib/custom-category.ts`)

The `/confronta` wizard builds a `CategoryDefinition` at runtime from
user input. The slug is fixed to `CUSTOM_SLUG = "__custom__"` so it
never collides with built-in slugs. Share URLs for custom comparisons
encode the minimal definition + entries in a base64url payload and live
at `/confronta?d=<token>`.

## 6. Components & data flow

The interactive page is built around three layered components:

```
Comparator                ← state owner: entries[] + share + planner
├── EntryForm × n         ← single product row with the floating "name chip"
├── BulkPaste             ← paste many rows at once (zod-validated)
├── ResultsTable          ← ranked results with crown on rank 1
└── PurchasePlanner       ← two cards: cost-for-qty and qty-for-budget
```

- `Comparator` holds `entries: ProductEntry[]` in React state and
  persists it to `localStorage` under `qc:entries:<slug>`.
- It hydrates from three sources, in order:
  1. `?d=<token>` query (share URL → calls `decodeEntries`).
  2. `localStorage[qc:entries:<slug>]`.
  3. `category.sampleEntries` if both above are empty.
- `Comparator` accepts optional props `storageKey`, `shareBuilder`,
  `onEntriesChange` so `/confronta` can reuse it with a custom storage
  namespace and a custom share-URL builder.
- The hero banner stats use a `useCountUp()` hook that animates from
  `0` to the target value on mount with `requestAnimationFrame` +
  ease-out-cubic. Honours `prefers-reduced-motion`.

## 7. Persistence keys (localStorage)

| Key                          | Owner              | Purpose                                              |
| ---------------------------- | ------------------ | ---------------------------------------------------- |
| `qc:theme`                   | `ThemeToggle`      | `"light" | "dark"` (system default if unset)         |
| `qc:recent`                  | `recent.ts`        | Tagged `RecentEntry[]` (category slug OR custom name) |
| `qc:entries:<slug>`          | `Comparator`       | One slot per built-in category, last edited entries   |
| `qc:custom-category`         | `routes/confronta` | The `CategoryDefinition` built by the wizard          |
| `qc:custom-entries`          | `Comparator` (via `storageKey` from `/confronta`) | Entries for the current custom comparison |

The legacy `string[]` shape of `qc:recent` is auto-migrated on read by
`recent.ts` (each legacy string is reinterpreted as `{ kind: "category", slug }`).

## 8. Sharing (`src/lib/share.ts` + `custom-category.ts`)

Each comparison can be shared via URL. The payload is JSON,
base64url-encoded, versioned (`v: 1`):

- Built-in categories: `/{slug}?d=<token>` where `token` encodes
  `{ v, e: ProductEntry[] }`.
- Custom comparisons: `/confronta?d=<token>` where `token` encodes
  `{ v, c: MinimalCategory, e: ProductEntry[] }`.

The decoder strips the `?d=` from the URL after loading
(`history.replaceState`) so further edits don't keep the share token in
the bar.

The share button uses `navigator.share` when available (mobile) and
falls back to `navigator.clipboard.writeText` (desktop).

## 9. Styling system (`src/styles.css`)

- Tailwind v4 is loaded via `@tailwindcss/vite`.
- Design tokens (colors, radii, font, glow + glass) live as CSS
  variables on `:root` and `.dark` (light/dark themes).

  Tailwind v4's `@utility` directive (so `hover:` / `group-hover:` /
  `focus:` variants actually generate selectors):
  - `brand-gradient-text` — clipped-to-text gradient (color: transparent

  - `brand-gradient-bg` — gradient background-image
  - `brand-gradient-border` — 1px gradient ring via mask-composite
- Section h2 headings get a `SectionIcon` (small gradient badge) +
  a 2px gradient separator (`brand-gradient-bg h-[2px]`).
- The fixed topbar uses the `topbar-surface` glassmorphism utility.

## 10. SEO

- Per-route meta is centralised in `src/lib/seo.ts`.
- Canonical links are emitted as `<link rel="canonical">` (not `<meta>`).
- `og:url`, `og:image`, `twitter:image` use `${VITE_SITE_URL}/og-image.png`.
- JSON-LD on `/{category}`: Article + BreadcrumbList + FAQPage (when
  the category has FAQ).
- `/sitemap.xml` is auto-generated from `CATEGORIES`. The legal pages
  (`/terms`, `/privacy`, `/cookie`, `/contatti`, `/confronta`) are
  intentionally NOT in the sitemap; `/confronta` is also `noindex,follow`.
- All routes set `<meta name="robots" content="index, follow">` except
  `/confronta` (which is `noindex, follow`).

The repo is connected to **Cloudflare Workers Builds** (the CF-native

- Production branch: `main`

- Deploy command: `bunx wrangler deploy`

## 12. Cloudflare infrastructure

The whole stack is on Cloudflare:

- **Registrar**: domain `qualeconviene.app` registered on Cloudflare
  Registrar. No need to change nameservers.
- **DNS zone**: managed in CF. Records:
  - `qualeconviene.app` → Worker custom domain (apex, proxied).
  - `www.qualeconviene.app` → CNAME → `qualeconviene.app` (proxied).
- **TLS**: automatic. `.app` is HSTS-preloaded so HTTPS is mandatory
  by browser. CF's "Always Use HTTPS" is enabled.
- **Workers**: a single Worker named `quale-conviene` serves SSR HTML +
  static assets. Account-level workers.dev subdomain visible in the
  dashboard.
- **www → apex redirect**: a Redirect Rule (template "Redirect from
  WWW to root", 301, preserve path) handles `www.*` traffic. The www
  CNAME must be **proxied** for the rule to fire.
- **Cache Rules**: HTML is configured to be edge-cached. Status note:
  Worker responses bypass the edge cache by default, so when the rule
  was first added the HTML still returned **no** `cf-cache-status`
  header. If/when caching needs to be guaranteed, switch to the Cache
  API inside the Worker (`caches.default.put/match` + `s-maxage`
  headers). Static assets (`/favicon.svg`, `/manifest.json`,
  `/assets/*`) are already cache-HIT.
- **Web Analytics**: handled automatically at the edge for this zone
  (it's a proxied CF zone). The JS beacon (`data-cf-beacon`) is wired
  but typically left disabled (no token) since the edge analytics are
  enough.
- **Workers Builds**: connected to the GitHub repo; deploys on push to
  `main`.
- **No KV / R2 / D1**: the app is fully stateless. All user data lives
  in `localStorage` on the client.

## 14. Conventions

- **Code is English, copy is Italian.** Identifiers, comments,
  filenames, commit messages: English. UI strings, page content, FAQ
  bodies, error messages shown to users: Italian.
- **Formatting**: Biome handles it. Indent is tabs (newer files) or
  2-space (legacy files); both pass because Biome reformats on save.
  Strings use double quotes.
- **Imports**: `#/*` is a path alias for `./src/*` (see
  `package.json → imports`). Components import via `#/components/...`,
  libs via `#/lib/...`, etc.
- **Git workflow**: commit locally freely, but push only on explicit
  user instruction (see `~/.claude/.../feedback_no_auto_push.md`).

## 16. Roadmap / known gaps

The list below captures the gaps in the current product. Order is
roughly by leverage (impact / effort). None of these is blocking; the
app works well today. Pick them up when there's appetite.

### High leverage — do these first

- **Dynamic OG image per category.** Today every shared link
  (WhatsApp, Twitter, LinkedIn, etc.) renders the same generic
  `/og-image.png`. Generating a branded PNG per category — name,
  background gradient, `€/X` label — would make every share visually
  distinct and shareable. Implementation path: a Worker endpoint
  (`/og/{slug}.png`) that uses `satori` or `@vercel/og` to render JSX
  to PNG at the edge. Set the response `Content-Type: image/png` and a
  long `Cache-Control` (these are deterministic by slug). Roughly half
  a day of work, big upside on social-driven traffic.

- **Lightweight backend for saved comparisons.** Today all state lives
  in `localStorage` and the only "share" is the `?d=` token in the URL.
  Adding a tiny persistence layer (Cloudflare KV or D1) with a
  link-as-token model (no auth: writing creates a short ID, fetching
  decodes it) turns every shared comparison from a one-shot URL into a
  persistent, named asset. Useful for: "my weekly shopping list", "the
  detergent comparison I keep updating". Stays GDPR-friendly because
  the link itself is the credential — no accounts needed. ~2 days.

- **Product analytics (Plausible / Umami / PostHog).** CF Web
  Analytics tells you page views and Core Web Vitals — not which
  categories convert, where the funnel breaks, how many shares
  actually get clicked. Plausible is the cleanest fit for the
  privacy-first promise of the site (no cookie banner, ~$9/mo) or
  Umami self-hosted on a CF Worker (free, more work). Without this
  data, prioritisation is blind. ~1 hour to set up.

- **CI runs the test suite.** Workers Builds today only runs the
  build step. A push that breaks `bun run test` ships to production
  anyway. Adding a GitHub Action that runs `bun run test && bun run
  check && bunx tsc --noEmit` on every push is ~10 minutes of work
  and prevents regressions on the math (`pricing.test.ts`),
  share-URL round-trip (`share.test.ts`), and bulk-paste parser
  (`bulk-paste.test.ts`).

### Medium leverage

- **Blog / articles section (`/blog`).** One or two articles a month
  on adjacent topics ("Quanto è aumentato il prezzo del latte UHT nel
  2026", "5 errori al supermercato che ti fanno spendere di più",
  category round-ups). Each article gives Google a fresh page to index
  AND a chance to internally link to the comparator of the relevant
  category. New surface area for SEO without changing the core
  product. ~half a day per article.

- **Custom wizard discoverability.** `/confronta` is hidden behind a
  CTA at the bottom of the home and the empty-search hook. Lots of
  users won't discover it. Possible improvements: a more prominent
  card near the top of the home; pre-filled wizard templates ("I 3
  detersivi più venduti", "Fardelli d'acqua sotto 0,20 €/L", "Mix di
  patatine"); a "create new" entry in the topbar; an onboarding
  banner the first time a search yields 0 results.

- **Error & performance monitoring.** No Sentry / no error capture
  today. A 500 in production is invisible until a user reports it.
  Sentry's free tier (5k events/month) is more than enough; the SDK
  wraps the TanStack Start error boundary in a few lines. While
  we're there, RUM with Web Vitals would surface the slowest pages.

- **OCR / smart bulk paste.** The current `BulkPaste` flow expects
  text in a roughly tabular form. Most users have a phone with the
  product photo in front of them. A future iteration could OCR a
  receipt or scan a supermarket shelf label (CF doesn't have OCR
  primitives — needs an external API like Cloud Vision or
  Tesseract.js client-side).

### Lower leverage / future bets

- **i18n.** Today Italian only. French and Spanish would 3-5× the
  addressable market. The category content is translatable but
  significant work (60+ pages of long-form copy). Stack supports it
  (TanStack Router has i18n patterns) but the cost is mostly in
  translated content quality, not code.

- **Browser extension / bookmarklet.** "I'm on the Esselunga website
  and want to compare these products" → one-click adds them to a
  comparison on `qualeconviene.app`. Needs a parser per supermarket
  e-commerce site (a few dozens are dominant in Italy: Esselunga,
  Coop, Conad, Carrefour, Lidl Online).

- **PWA → Google Play via TWA.** The site is already a valid PWA. A
  Trusted Web Activity wrapper publishes it to Play Store with the
  same codebase. Discoverability + native-feeling install.

- **Newsletter / RSS.** Once `/blog` exists, a small newsletter or
  RSS feed for "new categories / new articles" gives a retention
  channel beyond `localStorage` recents.

### Already-listed infrastructure improvements

See **section 12 → "Other CF improvements worth doing later"** for the
Cloudflare-side checklist (Tiered Cache, Early Hints, DNSSEC, WAF
Managed Ruleset, Bot Fight Mode, Rate Limiting, Health Check, SPF/DMARC
email hardening). All free or low cost, total setup time well under
an hour.
